# eco-hash Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convertir la copia de solaxy-mvp en eco-hash, una plataforma de planes de hashrate (TH/s) para minar Bitcoin con saldo y retiros en BTC, y una cara nueva. Publicarla en GitHub y en Vercel.

**Architecture:** Se conserva la arquitectura: Next.js 16 (App Router, cacheComponents), Drizzle con libSQL/Turso, Better Auth y los pagos existentes. El dominio puro `lib/energy` se reemplaza por `lib/mining`, que el servidor y el navegador comparten. El saldo pasa de pesos a sats, y los retiros pasan a ser en BTC. La UI se rehace sobre nuevos tokens de diseño.

**Tech Stack:** Next.js 16.4, React 19.3, Tailwind 4, Drizzle 0.45, libSQL, Better Auth, Vitest 5, Playwright, viem (sha256 para base58check).

**Spec:** `docs/superpowers/specs/2026-11-20-eco-hash-design.md`

## Global Constraints

- Planes: `h100` Nonce 100 TH/s $4.600, `h250` Bloque 250 TH/s $4.450, `h500` Cadena 500 TH/s $4.300, `h1000` Génesis 1.000 TH/s $4.200 (COP por TH/s al mes). Contrato de 3 meses, periodos de 30 días y 15 días de gracia.
- Hashprice inicial: 42 sats por TH/s al día. Capacidad inicial de la granja: 30.000 TH/s. Retiro mínimo: 50.000 sats.
- `sats = TH/s × hashprice × días`, lineal y 24/7. El hashprice se guarda en cada periodo al activarlo.
- Saldo en sats = floor(minado) − retiros `confirmada` − retiros `por_aprobar`. Nunca negativo.
- Sigla de las referencias: `ECH`. Tabla de migraciones: `__ecohash_migrations`. Cuenta de pruebas: `pruebas@eco-hash.local`.
- Textos en español de Colombia. No se presentan cifras simuladas como mediciones: los datos de la red se rotulan «referencia» si la API no responde.
- Ningún texto, color ni tipografía de la marca anterior (X green Energy, Solaxy, Eclipse, reloj solar) en la interfaz final.

## Review Focus

1. Dos retiros simultáneos con el saldo justo: solo uno aparta los sats (la suma de comprometidos se compara dentro del INSERT). → Task 4.
2. Una dirección BTC mal escrita (checksum inválido, mayúsculas mezcladas en bech32, testnet en producción) se rechaza con un mensaje claro. → Task 2.
3. El admin cambia el hashprice a mitad de un mes: los periodos ya activos conservan su valor y solo los nuevos usan el nuevo. → Task 3.
4. El admin baja la capacidad por debajo de los TH/s ya contratados: se rechaza. → Task 3.
5. mempool.space o CoinGecko caídos: el inicio y el panel se muestran con valores de referencia rotulados. → Task 5.
